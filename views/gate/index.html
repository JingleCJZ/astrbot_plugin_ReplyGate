系统提示词块（沉默机制） 读取中…
消息打断同一用户在你回答的过程中又发消息，是否停掉正在生成的那条
打断强度 弱打断：不取消在途生成，但把它即将发出的那条回答作废丢弃，只回复新消息（省得白杀正在跑的工具）。 强打断：直接取消在途执行，旧回答不会产生，再回复新消息；受次数预算限制，超限或接口不可用会自动降级为弱打断。 两种模式都只会让用户看到“新回答”，不会出现旧回答。
读取中…
超时（强 / 弱打断都生效） 超时后的打断不启动判定流程：新消息离开这个窗口后，既不会触发强打断、也不会启动判定模型， 正在准备（或正在分段发送）的那条回答按原样继续。
判定设置仅弱打断 阈值 0-100：判定模型评分 > 阈值才重新生成，否则保留旧回答。 上文条数：从主模型开始生成那一刻往前再多带几条消息。 超时(秒)：判定模型单次请求超时，失败才按失败策略收尾。 输出上限：判定只输出一行 JSON，思考模型给 64 会把预算全花在思考上。
判定模型仅弱打断（选择后自动保存） 从已配置的对话模型里选一个（下拉读取全部模型）。建议用与主模型不同族的小模型、并配合「思考=关」；留「跟随当前会话模型」表示不单独指定。

分句发送插件按分隔标识把一条回答拆成多段、逐段发送，段间可等待
分句标识 插件按这个标识切开模型输出、逐段发送；输出里没有这个标识就整段发（流水会记一条「分句·跳过」及原因）。 切段时会跳过夹在公式里的分隔符；模型用的提示词里请写同一个标识。
段间等待 对数：log_底数(本段字数) 秒；一次函数：初始值 + 本段字数 ÷ 增长率 秒。 等待越久越容易被新消息打断，每段发送前后都会检查有没有被打断。

消息缓冲只影响主模型什么时候收到消息；单次时间 0 秒即关闭
单次缓冲时间 每来一条新消息就重新计时；安静满这么久才把这批消息一起交给主模型。 设为 0 = 不缓冲（消息立即交给主模型）。 缓冲只影响主模型：撤销延迟消息、触发判定/打断、记录流水都在消息到达时立即发生。

最大总缓冲时间 从第一条被缓冲的消息开始计时：到点无论单次计时是否满足，都结束缓冲、把已攒的消息交给主模型。 防止对方一直发消息导致无限缓冲。必须 ≥ 单次缓冲时间。
